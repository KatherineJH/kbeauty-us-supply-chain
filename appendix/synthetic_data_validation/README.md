# 부록 — 합성 운영 데이터 검증

> 본문 분석은 **실제 공개 데이터**(미국 Census 수입 통계)로만 결론을 낸다.
> 이 부록은 같은 저자가 그 공개 데이터를 기준으로 만든 **합성 운영 데이터**를 어떻게 검증했는지 보여 준다.
> 합성 데이터에 대해서는 "설계 문서대로 만들어졌는가"만 판단하고, 시장에 대한 결론은 내리지 않는다.

## 왜 합성 데이터가 필요했나

K-뷰티 브랜드의 주문·재고·선적 데이터는 공개되지 않는다. 미국 수출 지연에 대응하는 의사결정 서비스를 개발·시연하려면
SKU·창고·일 단위 운영 데이터가 필요했다. 그래서 본문의 Census 공개 데이터(물량 규모, 운송수단 비중, 리드타임 분포)를
기준값으로 삼아 가상 브랜드 2곳의 운영 데이터를 생성했다.

| 항목 | 값 |
|---|---|
| 기준선 | `FINAL_2026_H1_SYNTHETIC_DATA` (후보 2 + overlay v1_run1) |
| 규모 | 표 27개, **1,323,211행** |
| 기간 | 2025-01-01 ~ 2026-06-30 (546일) |
| 구성 | 회사 2, SKU 50, 창고 6(한국·미국 서부·미국 동부), 주문 171,888, 주문 상세 257,690, 선적 166, 재고 일별 60,060 |

## 검증 방법 — 11개 노트북

모든 노트북은 **질문 → 데이터 → 방법**으로 시작해 **발견 → 한계**로 끝난다. 원본·manifest·DDL은 읽기만 한다.

| # | 노트북 | 무엇을 확인했나 |
|---|---|---|
| 00 | 기준선 무결성 | 파일 해시 47개, 표별 행 수를 manifest와 대조, 헤더를 PostgreSQL DDL(v6.2)과 대조, Parquet 캐시 생성 |
| 01 | 데이터 품질 | 결측, PK·UNIQUE 80개 제약, FK 57개 고아, 범주 허용 목록 50개 열, 재고 수지(on_hand = reserved + available) |
| 02 | 기준 데이터 | 회사·SKU·창고·운영 규칙이 설계 문서와 같은가 |
| 03 | 수요 | 일별 주문 수를 설계 식으로 재구성, 무작위 요소의 분포 검정 |
| 04 | 재고 | 보충 정책 재구성, 품절 에피소드와 재고 커버 |
| 05 | 선적·리드타임 | 계획·실제 운송 기간 재구성, 지연 원인 |
| 06 | 출고·서비스 | 출고, 정시율, 대기 원인 |
| 07 | 데이터 파이프라인 | 수집 실행·변경 기록, 특정 시점의 상태 복원 |
| 08 | 분석 계층 | 지연 대응 엔진의 판단 사례를 사후 데이터와 대조 |
| 09 | 통계 분석 | **사전에 정한 가설** H1~H6 검정(Holm 다중비교 보정, 부트스트랩 신뢰구간, 군집 강건 표준오차) |
| 10 | 종합 | 신뢰도 점수표, 데이터 카드, 모델링용 패널·기준선, 함정 목록 |

## 결과

### 사전 가설 검정 ([`tables/hypothesis_tests.csv`](tables/hypothesis_tests.csv))

| 가설 | 결과 | 의미 |
|---|---|---|
| H1 수요 분포 | 주문 상세 수 산포 지수 0.969, 판매 단위 2.401 (설계값 2.45를 신뢰구간이 포함) | 과산포는 SKU 이질성이 아니라 **주문당 수량 분포** 때문 → 안전재고는 복합 포아송으로 |
| H2 주말·행사 효과 | 주말/평일 1.203 (설계 1.2), 행사 배율이 세 등급 모두 설계값 포함 | 생성기가 의도대로 작동 |
| H3 채널 × 등급 | Cramér's V 0.005, 0.006 | 독립 |
| H5 예측 한계 | 28일 이동평균 WAPE 0.379, **참 평균을 아는 예측 0.370** | 개선 여지가 0.8%p뿐 → 복잡한 모델이 이길 수 없는 데이터 |
| H6 품절 요인 | 재고 커버(전날) 승산비 0.068. 커버를 통제하면 수요 크기 효과가 사라짐 | 품절 = 커버 소진. "저회전 SKU가 더 자주 품절"은 착시 |

### 이 검증에서 얻은 원칙

1. **하한 기준선을 함께 보고한다.** 모델 성능은 이동평균(넘어야 할 선)과 참 평균 예측(넘을 수 없는 선) 사이에 놓고 읽는다.
   하한보다 좋은 결과가 나오면 성능이 아니라 **누수를 의심**한다([`tables/forecast_benchmark.csv`](tables/forecast_benchmark.csv)).
2. **합성 데이터에는 설계에 적은 것 이상의 구조가 없다.** 이 데이터로 "시장"을 분석하면 생성기의 가정을 다시 읽는 것에 불과하다.
   그래서 본문은 실제 Census 데이터로만 결론을 낸다.
3. **누수 열을 명시한다.** 당일 재고와 예약 수량은 수요 예측의 누수 열이다
   ([`tables/modeling_readiness.csv`](tables/modeling_readiness.csv)).
